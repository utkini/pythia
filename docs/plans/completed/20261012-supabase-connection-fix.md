# Исправление подключения к Supabase

## Overview

Исправить нормализацию `DATABASE_URL` для SQLAlchemy + asyncpg: URL с
`sslmode=require` должен передавать драйверу `ssl=require`. Одна функция
используется приложением и Alembic, поэтому исправление должно покрыть оба пути.

Транскрипция остаётся через OpenAI API. Локальный faster-whisper не входит в
актуальный план работ. Схема БД, Telegram и зависимости не меняются.

## Context (from discovery)

- `pythia/database.py`: `async_database_url()` сейчас заменяет только схему URL;
  для `postgresql+asyncpg://` возвращает строку сразу, оставляя `sslmode`.
- `tests/test_database.py`: существующий тест Supabase воспроизводит ошибку.
- `alembic/env.py`: использует тот же нормализатор перед созданием движка.
- В установленном SQLAlchemy диалект asyncpg передаёт query-параметры URL
  драйверу как аргументы; параметр подключения asyncpg называется `ssl`.
- Последний запуск `uv run pytest -q`: 16 passed, 1 failed, 1 skipped.
  Пропущен интеграционный тест миграций, требующий отдельную PostgreSQL БД.

## Solution Overview / Technical Details

Разбирать URL через `sqlalchemy.engine.make_url`, изменять схему и query через
API объекта URL, затем возвращать строку через
`render_as_string(hide_password=False)`. Это сохраняет пароль для подключения,
включая percent-encoded символы; возвращённую строку не логировать.

Правила преобразования:

| Вход | Результат |
|---|---|
| `postgres://` или `postgresql://` | `postgresql+asyncpg://` |
| `postgresql+asyncpg://` | Схема сохраняется, query также нормализуется |
| Только `sslmode=<value>` | Переименовать в `ssl=<value>` |
| Только `ssl=<value>` | Сохранить |
| Оба параметра с одинаковым значением | Оставить один `ssl` |
| Оба параметра с разными значениями | `ValueError` с описанием конфликта без URL/пароля |
| Без SSL-параметров | Не добавлять SSL-настройки |
| Другая схема | Вернуть исходную строку, сохраняя прежнее поведение |

Не заменять режимы SSL на булевы значения и не ослаблять их. Остальные
query-параметры сохранять. Повторный вызов нормализатора не меняет результат.

## Testing Strategy

- Unit-тесты преобразования URL и сохранения реквизитов, без внешней сети.
- Проверка аргументов диалекта SQLAlchemy через `create_connect_args()`:
  до asyncpg должен доходить `ssl`, а не `sslmode`, с исходным паролем.
- Полный набор: `uv run pytest -q`.
- Миграции и реальное подключение проверять отдельно на выделенной тестовой БД;
  отсутствие такой БД явно отмечать, не считать проверку выполненной.

## Post-Completion

На отдельном тестовом проекте Supabase выполнить `SELECT 1` через движок
приложения и проверить миграции через существующий интеграционный тест с
`PYTHIA_TEST_DATABASE_URL`. Миграции изменяют схему: использовать только
выделенную для этой проверки БД. Не выводить строку подключения в логи.

Если реальные проверки выявят отдельные проблемы доступности host, IPv6,
pooler или сертификатов, записать их отдельными задачами. Текущий подтверждённый
дефект ограничен передачей параметра `sslmode`.

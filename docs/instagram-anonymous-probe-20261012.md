# Проверка анонимного доступа к Instagram — 2026-10-12

## Цель

Проверить альтернативу текущему Instaloader без пользовательского session-файла:
публичный профиль → три свежих Reels → метрики → видео со звуком.

## Исследованные изменения upstream

- [Instaloader PR #2722](https://github.com/instaloader/instaloader/pull/2722):
  в первом патче альтернативное получение профиля и публикаций использует
  `context.get_json("api/v1/feed/user/{username}/username/", params={"count": 12})`.
  Это лента публикаций, а не доказательство получения трёх последних Reels.
- [Fork raycheung](https://github.com/raycheung/instaloader/blob/master/instaloader/structures.py):
  просмотренный `get_reels()` разделяет авторизованный и анонимный доступ.
  Изменённый путь с `profile_reels_doc_id` используется при авторизации;
  анонимная ветка оставляет `7845543455542541`, как установленный Instaloader.
  Ветки upstream изменяемые; этот вывод относится к просмотренному коду на дату проверки.

## Эксперимент

- Среда: Mac разработчика, установленный Instaloader 4.15.3.
- Профиль: `nike` — тот же публичный профиль, что в исходной ошибке.
- Новый экземпляр Instaloader; настройки Pythia и session-файлы не загружались.
- `max_connection_attempts=1`, `request_timeout=20`.
- Один вызов GET `https://www.instagram.com/api/v1/feed/user/nike/username/?count=12`.
- Код стороннего fork не устанавливался и не исполнялся; проверен конкретный
  запрос из прочитанного diff через установленную библиотеку.

Результат: `401 Unauthorized`, статус `fail`, сообщение
`Please wait a few minutes before you try again.`; Instaloader выбросил
`ConnectionException`. После отказа дополнительные запросы не выполнялись.

## Что подтверждено

Альтернативный feed endpoint не вернул данные в этом окружении при этой попытке.
Профиль и список Reels не получены; метрики, MP4 и наличие звука не проверены.
Сравнение со старым endpoint в тех же условиях не выполнено из-за ограничения.
Raspberry Pi в эксперименте не участвовал.

Ответ не позволяет отделить ограничение IP/сети от ограничения endpoint,
профиля или анонимного доступа. Он не доказывает необходимость авторизации
для всех публичных профилей и не доказывает невозможность самостоятельного сбора.

## Следующий диагностический шаг

После прекращения ограничения проверить обычную публичную страницу профиля в
браузере без авторизации и посмотреть, какие данные она фактически возвращает.
Если данные доступны, исследовать запросы этой страницы и сравнить их с
Instaloader. Если браузер показывает только вход или ограничение, зафиксировать
это отдельно, не принимать HTML страницы входа за отсутствие Reels.

Рабочий сборщик менять только после успешной проверки всей цепочки,
включая свежесть трёх Reels, метрики и скачивание видео со звуком.

## Дополнение: успешное скачивание по прямой ссылке через yt-dlp

Проверена одна Reel-ссылка, обнаруженная в публичной сетке профиля:
`https://www.instagram.com/nike/reel/DePzV26vLFB/`.

Использован yt-dlp **2026.08.19**, временно запущенный через uvx из PyPI.
Конфигурационные файлы, плагины и кеш yt-dlp отключены. Cookies, логин и
session-файлы не передавались. Повторные попытки отключены; это один запуск
extractor, который может выполнять несколько разных HTTP-запросов.

```sh
uvx --from 'yt-dlp==2026.08.19' yt-dlp \
  --ignore-config --no-plugin-dirs --no-cache-dir --no-playlist \
  --retries 0 --extractor-retries 0 --fragment-retries 0 \
  --socket-timeout 20 --max-filesize 100M --no-progress \
  --print after_move:filepath \
  -o '/tmp/pythia-instagram-probe/%(id)s.%(ext)s' \
  'https://www.instagram.com/nike/reel/DePzV26vLFB/'
```

Результат: успешное скачивание, код возврата 0. Предупреждение
`No CSRF token set by Instagram API` не помешало загрузке.

Проверка ffprobe:
- Контейнер MP4, размер 4 076 529 байт, длительность 30.030030 секунды.
- Видео VP9, 1080×1920.
- Аудио AAC, 44 100 Гц, 2 канала.

Обе дорожки полностью декодированы командой ffmpeg в null output без ошибок.
Наличие речи/смысл аудио не оценивались, запросы OpenAI не выполнялись.
Файл оставлен в `/tmp/pythia-instagram-probe/DePzV26vLFB.mp4`.

Подтверждено: один публичный Reel можно скачать без авторизации через yt-dlp
в текущем окружении, несмотря на окно входа в браузере. Это не подтверждает
работу на всех профилях, на Raspberry Pi, извлечение метрик или полноту списка
свежих Reels. Зависимости и рабочий сборщик Pythia не изменены.

Следующий этап: отдельно проверить получение метрик yt-dlp и надёжное
обнаружение свежих Reel-ссылок; затем интегрировать загрузчик по прямой ссылке.

## Дополнение: метрики трёх роликов и обнаружение по профилю

yt-dlp 2026.08.19 без cookies успешно получил метаданные всех трёх известных
ссылок. Видео повторно не скачивались. Счётчики отражают момент проверки:

| Reel | Дата (UTC) | Лайки | Комментарии | Просмотры |
|---|---|---:|---:|---|
| DePzV26vLFB | 2026-10-08 | 74072 | 1672 | null |
| Dd9Etk7R91I | 2026-10-01 | 49508 | 1575 | null |
| Ddl5eH-u4le | 2026-09-22 | 72597 | 1178 | null |

Подпись присутствует у всех трёх. Для второго и третьего extractor вернул
12 и 6 видеоформатов соответственно, но сами эти файлы не скачивались.
У первого `duration` в метаданных отсутствует, хотя ffprobe ранее определил
длительность скачанного файла. Отсутствующие просмотры нельзя считать нулём;
ранжирование по просмотрам при таких данных не обосновано.

В установленном коде `InstagramUserIE` имеет `_WORKING = False` и ожидает
старую структуру `entry_data.ProfilePage`. Поэтому загрузка профиля через этот
extractor не проверялась дополнительными запросами как заведомо надёжный путь.

Отдельный HTTP GET `https://www.instagram.com/nike/` через requests без сессии
вернул HTTP 200, без редиректа на вход, 707547 байт HTML. В ответе есть заголовок
профиля и компоненты страницы/согласия cookies, но не обнаружены известные
shortcode, ссылки `/reel/` или media-объекты в JSON script-блоках. Это отличается
от ранее наблюдаемого DOM после отклонения необязательных cookies в браузере.
Простой разбор этого HTML не воспроизвёл сетку публикаций.

Итог: подтверждён путь «известная Reel-ссылка → подпись/дата/лайки/комментарии
и форматы видео», плюс полное скачивание и декодирование одного ролика.
Автоматический выбор трёх свежих Reels и получение просмотров не решены.
Практически готовым следующим изменением может быть поддержка прямых Reel-ссылок
в Pythia с yt-dlp, отображением неизвестных просмотров и без выдуманного рейтинга.
Для сохранения сценария по профилю нужен отдельный компонент обнаружения ссылок
с проверкой полноты и порядка публикаций. Рабочий код пока не изменён.

отдельный эксперимент с явным ограничением полноты. Для исходного требования
«три последних Reels по username» проверка пока не пройдена. На Raspberry Pi
этот браузерный сценарий не проверялся; встроенный браузер Codex не является
готовым компонентом серверного приложения.

# Pythia

Личный Telegram-бот для анализа от одного до трёх публичных Instagram Reels по прямым ссылкам. Для каждого ролика он получает лайки и комментарии, скачивает видео через yt-dlp, извлекает аудио и 8 кадров через ffmpeg, а затем использует OpenAI для транскрипции и смыслового анализа. Если ссылок несколько, в конце бот показывает, у какого ролика лучшая вовлечённость. Видео, аудио и кадры не хранятся после выполнения задачи.

## Возможности MVP

- 1–3 ссылки одним сообщением (через пробел или с новой строки) или `/analyze <ссылка> [<ссылка> …]` в личном чате:

  ```
  https://www.instagram.com/reel/AAA/
  https://www.instagram.com/nike/reel/BBB/?igsh=…
  ```
- Ссылки могут быть от разных авторов. Дубли пропускаются; больше трёх разных ссылок, профили, посты `/p/` и посторонний текст отклоняются целиком до начала загрузки.
- По каждому Reel — отдельный отчёт «Reel N»: ключевой кадр, лайки, комментарии, речь, текст на экране, темы, hook и CTA.
- Итог для 2–3 ссылок: `score = лайки + 3 × комментарии`, считается кодом без AI. Ролик без лайков или комментариев помечается «нет данных» и в рейтинг не входит; при равном score называются все лидеры. Просмотры yt-dlp не отдаёт, поэтому это оценка вовлечённости, а не охвата; возраст публикации показывается рядом.
- Ошибка одного ролика не останавливает остальные: запуск получает статус `partial`, а итог называет пропущенный Reel и причину.
- Только один заранее заданный Telegram ID может запускать обработку.
- История запусков (введённые ссылки, рейтинг в `analysis_runs.ranking_json`), метаданные и текстовый анализ в Supabase Postgres. Повторный анализ того же Reel создаёт новую запись в рамках нового запуска и не перезаписывает старую.
- Один анализ за раз; незавершённые запуски при рестарте помечаются `interrupted`.

## Режимы запуска

Есть два независимых профиля — выбирайте один:

- **Raspberry Pi + Supabase** — контейнер бота на Pi, управляемая PostgreSQL в Supabase. Использует [docker-compose.yml](docker-compose.yml) и `.env`.
- **Полностью локальный** — контейнеры бота и PostgreSQL на одной машине. Использует [docker-compose.local.yml](docker-compose.local.yml) и `.env.local`.

В обоих случаях нужны Telegram Bot Token и OpenAI API key. Instagram-логин и session-файл не нужны: yt-dlp скачивает публичные Reels анонимно.

### Raspberry Pi + Supabase

```sh
cp .env.example .env
# заполните .env: укажите строку подключения Supabase
docker compose build
docker compose run --rm bot alembic upgrade head
docker compose up -d
```

В этом режиме локальный контейнер PostgreSQL не создаётся. `.env.example` содержит обычный Supabase URL; приложение преобразует его для asyncpg.

### Полностью локальный Docker-стенд

```sh
cp .env.local.example .env.local
# заполните токены и модели в .env.local
docker compose -f docker-compose.local.yml up --build
```

Compose сам запускает PostgreSQL, ждёт его healthcheck, применяет Alembic-миграции сервисом `migrate`, и только затем запускает бот. Локальная база доступна на `localhost:5432` и сохраняет данные в Docker volume `pythia-local-postgres`. Для удаления вместе с данными: `docker compose -f docker-compose.local.yml down -v`.

Логи в любом режиме: `docker compose … logs -f bot`.

## Локальная разработка

```sh
uv sync --all-groups
# сначала поднимите только локальную БД командой выше
set -a; source .env.local; set +a
uv run alembic upgrade head
uv run pytest
uv run pythia
```

При прямом локальном запуске `.env.local` указывает на `localhost`; внутри локального Docker-стенда Compose заменяет адрес на сервис `db`. `DATABASE_URL` может быть стандартным Supabase PostgreSQL URL; приложение само адаптирует его для async SQLAlchemy. Миграции — единственный механизм изменения схемы базы данных.

В приложении и миграциях параметр URL `sslmode` автоматически преобразуется в `ssl` для asyncpg с сохранением режима (например, `sslmode=require` → `ssl=require`). Если указаны оба параметра, их значения должны совпадать; конфликт приводит к ошибке конфигурации. Для локального URL без SSL-параметров настройки SSL не добавляются.

## Обновление на Raspberry Pi

Ревизия `20261015_0002` меняет схему (подборки Reels, рейтинг, уникальность Reel в рамках запуска). Перед обновлением сделайте резервную копию базы Supabase, затем:

```sh
git pull
docker compose build
docker compose stop bot
docker compose run --rm bot alembic upgrade head
docker compose up -d
```

Откат миграции возможен, только пока один и тот же Reel не сохранён в нескольких запусках и у всех запусков есть автор; иначе downgrade остановится на ограничениях, не удаляя данные.

## Ограничения

Используйте только публичные Reels и соблюдайте правила Instagram и применимое законодательство. Анализ профилей и поиск свежих роликов профиля больше не поддерживаются — присылайте прямые ссылки на Reels. yt-dlp не гарантирует доступ к любому ролику, а Instagram может ограничить запросы; бот сообщит об ошибке по конкретному Reel вместо бесконечных повторов. Максимальный размер загрузки — 100 MiB для файлов с известным размером. Лайки и комментарии разных авторов и разного возраста сравнимы лишь приблизительно. Этот MVP не подписывается на аккаунты и не выполняет анализ по расписанию.
